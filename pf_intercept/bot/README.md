# 对手信息与牌桌管理

`BotBridge` 是 headless 与 MITM 代理共用的对局接入层，负责游戏状态、对手信息、选桌和资金限制。
下注决策见[决策引擎](../../pokerfate/decision/README.md)，外部调用契约见 [API 接入](../../pokerfate/INTEGRATION.md)。

两种模式共用运行参数、会话处理、对手模型和牌桌管理。
headless 通过 `--bb` 自动进桌；proxy 指定 `--bb` 时在客户端登录后自动进桌，未指定时由客户端选择首次现金桌。
proxy 中手动离桌或站起会暂停自动选桌，重新入座后恢复。
比赛房（SNG / MTT）由客户端玩家操作，好友房不自动锁仓、补码或选桌。

## 控制参数

两种入口使用同一份 [RunOptions](../options.py)，参数名、默认值和校验规则一致。
命令行参数只作用于当前进程，不修改 Python 全局配置。

| 参数 | 默认值 | 含义 |
|---|---|---|
| `--bb` | 0 | 首选现金桌大盲；headless 不进桌，proxy 等待客户端首次入座 |
| `--buyin-bb` | 100 | 首次及后续自动匹配的目标买入深度 |
| `--max-auto-rebuy` | 1 | 净亏损额度为 `(1+N)×100BB`，允许 0–20 |
| `--profit-lock-bb` | 200 | 桌上筹码达到多少 BB 后锁仓 |
| `--topup-below-bb` | 70 | 补码触发线；0 关闭，补码目标为 100BB |
| `--stakes` | 按起始场次生成 | 场次偏好顺序，如 `10000,5000`；起始场次总排第一 |

`--max-auto-rebuy` 限制净亏损，不是实际买入次数。越界参数在启动前报错。
`--buyin-bb` 不改变破产续入和锁仓重进的 100BB 目标。
换桌等待与冷却（`TABLE_SELECT_*`）和锁仓重进等待（`PROFIT_LOCK_REENTER_DELAY_SEC`）是
[pf_intercept/config/__init__.py](../config/__init__.py) 里的常量，不是命令行参数，也不读环境变量。

## 信息输入

| 输入 | 处理位置 | 提供的信息 |
|---|---|---|
| 房间、座位、盲注、行动与结算消息 | [bridge.py](bridge.py) | 当前牌局、真实行动历史和结算 |
| `/player/gameData` | [game_api/gamedata.py](../game_api/gamedata.py) | 对手历史统计 |
| 房内机器人数 `rb_num` 与进出记录 | [core/robots.py](../../pokerfate/core/robots.py) | 由计数证据确认的玩家标签 |

数据按稳定 UID 关联，名字只用于展示。选桌由 [table_policy.py](../table_policy.py) 判断、桥接层执行。

### 对手历史

两种入口使用当前登录会话的 HTTP 凭证、线路、渠道和客户端版本。
proxy 核对登录捕获文件中的 UID、登录 key 与当前客户端一致，才启用该账号的 HTTP 请求。
成功返回且有历史手数时，桥接层调用 `seed_from_server()` 初始化对手模型，API 未就绪时先缓存。
服务端手数、VPIP、PFR 覆盖对应字段，AF、WTSD 作为先验；服务端未提供的分街和面对特定行动的统计继续本地累计。
查询失败不等于零手数，也不据此判定新人。

### 人机识别

本地名单保存在 `local/models/robots.json`，依据服务端 `OtherLeaveRoomBRC.rb_num` 与玩家进出记录推断：

- 未知账号数恰好等于剩余机器人数时，可确认这些账号是人机；机器人数为零时可确认当前玩家是真人。
- 两次计数的变化结合期间进出记录，约束进出账号的身份。进房广播只登记玩家，不单独提供机器人数证据。
- 人数不完整时不推断；证据冲突时撤销确定标签。计数与已有标签冲突会记录 `robot_count_mismatch`。

只有计数证实的账号标为人机。未知账号在选桌时计入真人侧，但不因此获得“已确认真人”的标签。
UID 区间、名字、头像和预行动不作为人机证据。

### 学习筛选

按每手发牌名单应用与选桌相同的桌况规则，不要求实际发生换桌：

- 没有真人或真人少于人机：整手不更新玩家统计，不采集训练、校准及河牌价值尺度样本。
- 真人不少于人机：真人照常记录，人机不进入训练行；仍有人机未弃牌时，不采集 hero 胜率校准或河牌价值尺度样本。
- 没有人机：正常记录和学习。

回放与离线训练同样排除人机样本。CFR 的池子基准和相似玩家库排除人机，
但保留人机自身的历史记录，遇到该账号时仍可读取。策略日志 `hand_start.players[].robot` 记录本手标签。

## 自动选桌

记 H 为真人侧对手数（含未知），R 为已确认人机数：

| 桌况 | 处理 |
|---|---|
| H = 0 且 R ≥ 1 | 离桌；已发到牌时等当前手结束 |
| 空桌 | 持续 10 秒无人后换桌；有人进入则取消空桌计时，重新判断 |
| H ≥ 1 且 H < R | 未发到牌时离桌；已在打时连续 2 手成立后离桌 |
| 其余 | 留桌 |

自动匹配会等待大盲入局。离桌后随机等待 3–5 秒再匹配。
场次是偏好顺序：默认从起始场次由近到远，同距离先高后低，例如 `10000 → 20000 → 5000 → 2000 → 1000`。
两种入口均可用 `--stakes 10000,5000` 指定顺序，允许值为 1000 / 2000 / 5000 / 10000 / 20000。
起始场次总排在第一位：`--bb 10000 --stakes 5000,10000` 的实际顺序是 `10000 → 5000`。
起始盲注在此列表外且未指定 `--stakes` 时，仅在起始场次找桌。

同场连续 3 张桌不合格算一轮失败，冷却从 15 分钟逐次翻倍，最长 60 分钟；找到合格桌后清零。
在备选场次打牌时，优先场次冷却到期后会等当前手结束再回探：每场试 2 张桌，一并检查 10 分钟内到期的场次。
全部不合格就返回刚才可用的场次，后续回探间隔翻倍。

所有可用场次连续失败 3 轮后停在大厅并通知；因筹码或等级被服务器拒绝的场次，本轮运行不再尝试。
离开打过牌的桌子会通知原因和本轮盈亏。进出桌、匹配及各座位判定记入 `pf_intercept/logs/table_select.jsonl`。
锁仓、离桌恢复和停止流程进行中时，选桌不会另发匹配请求。

## 盈利锁仓

现金桌筹码达到锁仓阈值后，打完当前手离桌，确认并刷新余额后以 100BB 重进原房间。
阈值看桌上筹码，不是本轮累计净盈利。锁仓不清零会话盈亏，也不扩大净亏损额度。

## 净亏损上限

一次启动的净亏损上限为 `(1 + --max-auto-rebuy) × 100BB`。
BB 固定为本轮起始场次：显式指定时使用 `--bb`，proxy 未指定时使用客户端首次选择现金桌的盲注，换场后不重算。
例如起始 `--bb 20000 --max-auto-rebuy 2` 对应 600 万筹码。
会话盈亏累计服务端逐手结算，盈利抵消亏损；买入、补码和活动奖励不计入对局盈亏。

bot 自动买入或补码时，限制 **当前净亏损（最低计 0）＋桌上筹码＋新增买入 ≤ 上限**。
破产续入以 100BB 为目标，自动匹配以配置的目标深度为准，额度不足时均向下取可容纳的档位。
锁仓重进带回的筹码少于刚取出的筹码，使用独立的重进流程。

买入滑块在 20–30BB 每 1BB 一档，40BB 起每 10BB 一档。
重新买入连最小 20BB 都放不下时，停止匹配和买入，停在大厅并通知；奖励服务继续运行。

## 桌上补码

一手结束后筹码大于零且低于补码触发线时，发送 `SetRebyREQ`，不离桌。
按滑块档位选择新增金额，使总筹码不超过目标且满足净亏损额度；例如目标 100BB 时，65BB 补 30BB，45BB 补 50BB。
服务器在发牌前通过 `RebyBRC(type="topup")` 确认，到账后发送通知。

额度不足最小档位时继续用现有筹码打牌。锁仓、选桌离桌或优雅停止期间不补码。
服务端拒绝或两手后仍未到账时，隔 30 手再试。

## 离桌恢复

自动选桌已启用的现金桌，意外收到成功的 `LeaveRoomRSP` 且仍有筹码时，
桥接层刷新余额，再按当前选桌策略恢复匹配，金额受净亏损额度约束。
主动停止、手动离桌暂停、锁仓及[校准积压暂停](#校准积压暂停)各自按对应流程处理。
headless 的连接中断和原桌恢复另见[断线自动重连](../headless/README.md#断线自动重连)。

## 校准积压暂停

摊牌样本先写进队列 `local/training/live_spool/`，由后台 worker 计算后更新 hero 胜率校准和训练样本。
worker 跟不上时队列会变大：

| 队列大小 | 处理 |
|---|---|
| ≥ 2GB | 推送“校准队列积压”提醒，对局照常 |
| ≥ 5GB | 推送“校准队列严重积压”；新一手开始时离桌，不再匹配、续入或锁仓重进 |
| 暂停后降到 2GB 以下 | 推送“校准队列已恢复”，解除匹配和买入限制 |

好友房不采集样本，不受这条限制。阈值是 [spool_showdown_calibration.py](../../pokerfate/calibration/spool_showdown_calibration.py) 里 worker 的默认参数。

## 数据核查与维护

```bash
.venv/bin/python -m analysis.robot_wire
.venv/bin/python -m analysis.table_policy_dryrun
```

前者根据历史网络日志核查人机证据，后者演练选桌判定。`robot_wire --write` 可重建本地人机名单。
需要按当前标签清理已有校准及训练数据时，使用 `analysis.robot_relearn` 的 `calibrator` 和 `rows` 子命令。
默认只报告；写入需停止 bot，先运行 `calibrator --apply`，再运行 `rows --apply`，工具会备份原文件。
