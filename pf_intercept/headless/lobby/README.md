# 大厅自动化

负责日常任务、活动领奖及完成任务所需的操作，由 headless 与代理模式共用，独立于德州决策。
登录与启停见[快速开始](../../../README.md#快速开始)，实战规则见 [对手信息与牌桌管理](../../bot/README.md)。

## 默认行为

登录成功并取得钱包基线后，后台开始检查。一般每 5 分钟补查一次，收到任务、邮件或结算推送时立即检查。
发展基金按服务器时间在 **UTC+8 的 07:00、19:00** 切换阶段，等待结算完成后领取。
日常任务按游戏日刷新（UTC+8 03:00），连续运行无需重启。

| 功能 | 自动执行的内容 |
|---|---|
| 发展基金、每日／每周／挑战任务 | 领取已完成奖励及活跃度宝箱；月卡任务只在资格有效时领取 |
| 七日签到、邮件 | 当日签到、领取未收附件；不补签、不删邮件 |
| 累签活动 | 领取当前期已解锁的签到奖励 |
| 大富翁 | 领取任务骰子、掷骰子、领取棋盘和里程奖励 |
| 主题活动、创作盛典 | 领取任务代币，按结缘晶片 → 筹码 → 礼物 → 其他物品的顺序兑换；不抽卡、不做投稿任务 |
| 协会经营 | 领取事务和赛季奖励；使用普通能量饮料派遣空闲牌手，必要时免费刷新；不购买、加速或升级事务所 |
| 灵猫风尚志 | 领取任务经验、已解锁等级和循环奖励；付费奖励仅限已经购买的刊物，不自动购买 |

活动期号、任务和奖励读取服务器状态及客户端配置表。同类活动换期后自动接续，结束后停止。
服务器当前期不在配置表中时暂停该活动并提醒。

## 为任务执行的操作

多个活动需要同一种操作时，按**最大缺口**执行，不把次数相加。完成后重新读取任务进度，日用量跨重启保留。
德州任务随正常对局推进；按下注额计的任务和无期限的挑战任务不会促使 bot 额外下注。

| 操作 | 行为与额度 | 单独关闭 |
|---|---|---|
| 彩球机、弹球 | 选服务端允许的最低档，每局不超过 1k；每种每天最多 100 局，每轮最多 5 局 | `--no-side-games` |
| 足球竞猜 | 仅为参与次数任务下注，每注 100k；选择未下注且最早开赛场次中奖池最大的结果，客户端档位不允许或余额不足时跳过 | `--no-football` |
| 奥马哈、德扑 AOF | 最低场凑手数，只付必要盲注／前注，免费过牌或弃牌；每种每天最多 15 手、3 张桌 | `--no-task-hands` |
| 查看界面、大厅互动、牌桌快捷语／表情 | 按任务缺口执行，互动表情仅用免费次数；每类每天最多 3 次 | `--no-task-reports` |
| 礼物 | 送出或回收最低价值礼物，按任务兑换碎片商城物品；补碎片时保留最便宜的 7 件礼物，每类每天最多 3 次 | `--no-gifts` |

任务手数安排在进入德州桌之前。跨游戏日出现新缺口时，每天最多主动离桌一次：打完当前手、完成任务手数，再匹配德州。
任务桌不进入德州引擎和 Live；任务执行失败后恢复德州匹配，离桌状态不明时先重连确认。

## 关闭功能

`--no-auto-rewards` 关闭整个大厅自动化。其余开关只关闭对应功能：

| 功能 | 参数 |
|---|---|
| 邮件 | `--no-mail` |
| 累签活动 | `--no-checkin` |
| 大富翁 | `--no-monopoly` |
| 主题活动 | `--no-theme` |
| 创作盛典 | `--no-creator` |
| 协会经营 | `--no-auto-dispatch` |
| 灵猫风尚志 | `--no-auto-battlepass` |
| 活动雷达 | `--no-radar` |

## 活动雷达

启动时及之后每 6 小时同步客户端热更新，对照现有能力查找新活动、无法完成的任务和额度缺口，并发送 Bark 提醒。
未处理的缺口持续提醒；活动结束和热更新通知去重。

本地 Web 的「雷达」页可忽略或恢复提醒，选择保存在 `local/state/lobby_ignores.json`，优先于项目内的忽略规则。
忽略只影响提醒，不会增加执行额度。

```bash
.venv/bin/python -m pf_intercept.headless.lobby            # 同步并查看报告
.venv/bin/python -m pf_intercept.headless.lobby --no-sync  # 只读本地配置表
```

## 记账与排错

本地和 VPS Live 分别展示本次启动的对局盈亏、已领取奖励筹码。换桌、补买、锁仓和重连不重置累计值。

- **对局盈亏**：服务器逐手净结算；买入、奖励和小游戏不混入。
- **奖励筹码**：确认领取的基金、任务、活动和邮件筹码；非筹码物品只记日志。
- **小游戏输赢**：彩球机、弹球和任务手数单独记账。
- **足球资金**：下注与邮件结算分别记录，不计入上述三项。

运行日志使用 `[REWARDS]` 标记：headless 写入 `pf_intercept/logs/headless.log`，代理写入同目录 `bot_worker.log`。
领取、消耗和失败明细统一追加到 `pf_intercept/logs/rewards.jsonl`。
后者带 UID、`run_id` 和任务／活动标识，可按本次运行查询。

| 日志事件 | 含义与处理 |
|---|---|
| `claimed` | 收到领取成功响应 |
| `claim_uncertain` | 请求结果或到账金额无法确认；先查服务器状态，不盲目重发 |
| `*_blocked` | 服务端拒绝，或领取后状态未变化；该动作通常暂停 6 小时，重启不清除 |
| `check_failed` | 检查失败，自动退避重试，最长间隔 30 分钟 |
| `auth_failed` | HTTP 凭证失效，停止自动领取，对局继续。headless 更新凭证后下次启动生效；代理模式在客户端重新登录后恢复 |

大厅使用当前登录会话的凭证和线路，HTTP 请求在后台执行，不阻塞牌局接收和心跳。
关闭时等待正在执行的请求结束并记账；结果不确定的金额在看板标注“另有待确认”。

## 维护入口

| 目录 | 职责 |
|---|---|
| `core/` | 调度、需求汇总、奖励账和忽略规则 |
| `routine/` | 基金、任务、签到、邮件 |
| `activities/` | 各类活动；代币商店共用 `token_shop.py` |
| `doers/` | 小游戏、任务手数、竞猜、互动和礼物操作 |
| `radar/` | 热更新、活动日历、能力缺口与提醒 |

[注册表](__init__.py) 统一声明模块、开关和推送订阅。新增活动时添加模块、注册项和模拟 HTTP/WSS 测试；
活动只上报任务缺口，复用执行者，不另建一套任务操作。
客户端资源与协议维护见 [资源维护说明](../../../pf_reverse/REVERSE_NOTES.md)。
