# Headless 运行与连接管理

纯 API 模式用保存的登录凭证直接连接游戏服务器，日常运行不需要手机或抓包代理。
安装、首次启动和停止见[快速开始](../../README.md#快速开始)；
选桌、买入、锁仓和止损见[对手信息与牌桌管理](../bot/README.md#控制参数)；策略配置见[决策引擎](../../pokerfate/decision/README.md)。

## 登录凭证

游戏登录需要客户端里网易易盾 SDK 生成的风控 token，程序无法自己登录，
只能让真实客户端经过临时代理登录一次，记下登录结果：

```bash
.venv/bin/python -m pf_intercept.headless.harvest_session
```

工具启动 `mitmdump` 并挂载 [capture_login.py](../../pf_reverse/capture_login.py)，
看到新的登录结果写入 `local/secrets/headless_session.json` 后自动退出。手机端步骤见[快速开始](../../README.md#1-采集登录凭证)。

| 参数 | 默认值 / 含义 |
|---|---|
| `--port` | `8080`，手机要填的代理端口 |
| `--lan-ip` | 自动探测；电脑有多个网卡、终端打印的 IP 不对时手动指定 |
| `--timeout-min` | 10 分钟内没等到新登录就退出 |
| `--upstream` | 指定上游代理，跳过自动探测，例如 `http://127.0.0.1:7890` |
| `--mitmdump` | `mitmdump` 的路径；不传时在 `PATH` 里找 |

工具先试直连游戏服务器，连不上才使用环境变量里已有的代理（`https_proxy`、`all_proxy`、`http_proxy` 等），不会猜测代理端口。
客户端可能用裸 IP 登录，所以抓包只用 `pf_intercept.config.MITM_IGNORE_HOSTS` 排除已知无关的域名，不用游戏域名白名单。

凭证通常约 30 天有效。遇到下面任一情况就重新采集：

- 启动报 `ResumeError`：凭证文件缺失、损坏或没有服务器列表。
- `headless.log` 出现 `[WSS] 登录被拒绝`。
- 大厅日志出现 `auth_failed`。

代理模式下，客户端每次经 mitmweb 登录都会更新同一个文件，见[代理模式](../proxy/README.md#登录凭证)。

## 进程参数

下面的参数两种入口都有，只有 `--hold` 是 headless 独有的。

| 参数 | 默认值 / 含义 |
|---|---|
| `--session-file` | `local/secrets/headless_session.json`，登录凭证文件 |
| `--stop` | 向本入口正在运行的实例发送优雅退出请求 |
| `--no-notify` | 关闭手机通知 |
| `-v` / `--verbose` | 增加控制台调试输出 |
| `--hold` | 30 秒；没传 `--bb` 时，登录后保持连接的时间 |

本机 Web 的地址和开关见 [Web 说明](../../pf_entertainment/README.md#监听与开关)。
远程上传用 `--no-remote-live` 关闭，配置与部署见[远程 Live](../../pf_entertainment/remote_live/README.md)。
大厅自动化的总开关和各模块开关见[大厅自动化](lobby/README.md#关闭功能)。

## PID 管理与优雅停止

无论在终端、后台还是 IDE 里启动，bot 都自己维护 `pf_intercept/logs/headless.pid`，记录实际的 Python 进程。
同目录的 `headless.lock` 持有独占文件锁，阻止同一份仓库重复启动。代理模式用的是 `proxy.pid` 和 `proxy.lock`。

`--stop` 不登录游戏。它核对 PID、锁和进程身份后发送 `SIGINT`，请求打完当前手再离桌。
命令返回只表示请求已发出，重启前要等原进程退出。离桌确认最多等 45 秒，之后关闭连接并收尾。
停止请求会禁止再进桌，并能打断登录、重连和恢复中的等待；选线探测结束后才退出。

正常退出或启动失败会删除 PID 文件。强制结束留下的 PID 文件不会被直接信任，下次启动时覆盖。
锁文件退出后保留，**运行时不要删除**，否则可能绕过重复启动保护。

## 断线自动重连

用 `--bb` 进桌后，遇到心跳超时、连接断开或发送失败时，进程和 Web 保持运行并自动重连。
重试间隔依次为 1、2、4、8、16、30 秒，之后一直 30 秒；从原线路开始，失败后轮换登录返回的其他线路。

重新登录后，以服务器的 `UserLocationRSP` 确认位置：

- 仍在房间：发送不带买入金额的 `EnterRoomREQ`，恢复原桌、筹码和当前行动。
- 已在大厅：清除旧桌状态，按当前选桌策略重新匹配，买入受净亏损上限约束。
  已停止买入、正在停止或因校准积压暂停时不重新匹配。
- 位置或房间快照超时：重新连接，再确认一次位置。

重连保留本轮统计、资金基线、模型、净亏损上限和奖励服务。
旧连接上还没发出的行动、续入和重进请求会被取消，当前牌局以新快照为准。
断线期间暂停奖励轮询，资金状态恢复后继续。

登录被明确拒绝、收到退出登录推送（包括在其他设备登录）或停服推送时，停止重连并记录原因。
已断线时收到停止请求会直接收尾；仍连着时按优雅离桌流程退出。
连接正常但意外离桌的处理见[离桌恢复](../bot/README.md#离桌恢复)。

## 网络与排错

bot 从登录结果的 `servers[].server_host` 和 `servers[].http_host` 取出游戏主机，
在选线前把它们加进本进程的 `NO_PROXY` / `no_proxy`，保留你原有的条目。
备用线路的 WSS 和 HTTP 请求也包括在内，启动命令不用手工设置绕过名单。
这只影响当前进程，不改系统代理或 shell 配置。

控制台输出即时刷新，文件日志另外保存；后台丢弃控制台输出或在 IDE 中运行都不影响写日志。
所有日志的位置见[日志](../../README.md#日志)。`headless.log` 里优先看：

| 记录 | 用途 |
|---|---|
| 启动错误 / `ResumeError` | 凭证文件问题，按[登录凭证](#登录凭证)重新采集 |
| `[WSS] 登录被拒绝` | 服务器拒绝这份凭证，重新采集 |
| `[NETWORK]` | 本次自动绕过代理的游戏主机 |
| `[RECONNECT]`、心跳超时 | 重连阶段、失败原因和最后收包时间 |
| `handler / queue_ms / handle_ms / backlog` | 超过 500 ms 的消息处理或排队，用来区分处理慢和积压 |

服务器已推进到下一个行动时，旧决策会被丢弃，不会补发过期的下注。
